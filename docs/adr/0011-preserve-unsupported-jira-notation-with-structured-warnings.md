# Preserve unsupported Jira notation with structured warnings

Jiro Flavored Markdown conversion uses symmetric best-effort behavior in both directions instead of failing the complete document when it encounters unknown, unsupported, or malformed source notation. Unsupported delimiters remain visible or become escaped literal target text, recognized body content continues through conversion, and callers receive source-positioned structured warnings separately from the converted document; the converter has no fixed input-size or nesting-depth limit, while fatal errors remain available for cancellation, output failures, and internal invariant failures. This favors usable representations of real Jira documents and partially understood JFM while preventing silent data loss or diagnostic text from contaminating either converted format.
