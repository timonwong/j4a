# Define bidirectional Jiro Flavored Markdown

jiro defines Jiro Flavored Markdown (JFM) as a bidirectional representation of supported Jira Markup semantics, separate from Markdown Input and unrelated Jira-oriented Markdown dialects: it canonicalizes rather than preserving source spellings, requires warning-free round trips for Jira emitted by Markdown Input, and leaves the existing `ToJira` implementation unchanged. JFM-to-Jira uses Goldmark with jiro-owned extensions, Jira-to-JFM uses a purpose-built Jira parser, and both adapt through a normalized semantic model with source spans so canonicalization and diagnostics are shared. Jira-specific semantics use reversible directives such as `:::panel`, `:::table`, `:::code`, `:link`, and `:image`; panels preserve nested structure and Jira attribute names rather than adopting ADF `panelType`, while Jira color macros use `<font color="value">...</font>` to match Jira Data Center and Server rendering. Conversion is symmetric and best-effort: unsupported or malformed notation remains visible, recognized content continues through conversion, deterministic source-positioned warnings are returned separately, and only cancellation, output failure, or an internal invariant is fatal, without fixed input-size or nesting-depth limits.
