# Separate reversible Jiro Flavored Markdown from Markdown Input

jiro treats Jiro Flavored Markdown (JFM) as a bidirectional string format for supported Jira Markup semantics, separate from the existing human-authored Markdown Input dialect. JFM may use jiro-owned generic directives such as `:::panel{...}`, `:::table`, and `:link[...]{target="..."}` for Jira-specific constructs and must round-trip them to canonical Jira Markup, while original source bytes and non-canonical spellings are intentionally not preserved. Every canonical Jira construct emitted by the existing Markdown Input converter is a mandatory warning-free round-trip baseline; this separation keeps Markdown Input simple and safe while avoiding compatibility claims with unrelated Jira-oriented Markdown dialects.
